# Заявки и Telegram

Админка показывает канбан: «Новые», «В обработке», «Завершённые». Карточку можно перетащить мышью в другую колонку или изменить статус через список на карточке (в том числе с телефона).

Для массового переноса отметьте карточки, выберите статус в панели над доской и нажмите «Применить к выбранным». За один раз можно изменить до 100 заявок. «Все видимые» выбирает карточки текущей страницы во всех колонках. При смене страницы или фильтра выбор сбрасывается. Поиск, статус и период работают совместно; настройки сохраняются в текущей вкладке браузера. Пагинация ограничивает число карточек в каждой колонке, но сервер пока загружает весь список заявок.

## Запуск бота на сервере

Если Telegram недоступен с основного сервера, используйте двусторонний Cloudflare Worker по инструкции `deploy/telegram-worker/README.md`.

1. Загрузите изменённые файлы `admin/`, `api/`, корневой `.htaccess` и отдельно приватный `.env` в корень сайта. `.env` исключён из Git. Не заменяйте существующий `config.local.php`.
2. Нужен PHP 8.1+ с cURL и mbstring, исходящий HTTPS к `api.telegram.org`, HTTPS у сайта и право PHP создавать/изменять корневой каталог `.private/`. Он хранит авторизованные чаты и счётчики попыток. Сохраните его при следующих обновлениях сайта. Для Apache доступ закрыт правилами `.htaccess`; для Nginx закройте URL `/.env` и `/.private/` в конфигурации сервера.
3. В `.env`: `TELEGRAM_BOT_TOKEN`, случайный `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_ADMIN_LOGIN`, `TELEGRAM_ADMIN_PASSWORD_HASH` (хеш PHP `password_hash`), `TELEGRAM_SITE_URL` (адрес сайта с HTTPS). Переменные окружения сервера имеют приоритет. Образец без секретов: `.env.example`.
4. После загрузки выполните на сервере `php api/telegram-setup.php`. Команда зарегистрирует webhook; повторный запуск допустим. Ключи не выводятся.
5. Откройте `@voronov_art_bot` в личном чате, отправьте `/start`, затем логин и пароль отдельными сообщениями. После успешного входа бот подпишет этот чат на новые заявки. `/stop` или `/logout` отключают подписку. Для повторного подключения снова нужен вход.

Вход ограничен пятью неудачными попытками за 15 минут на чат, а также 30 попытками за 15 минут для бота в целом. `/start` не сбрасывает ограничения. На ввод отводится 5 минут. Вебхук проверяет секретный заголовок Telegram, повторные обновления не обрабатываются. Пароль не записывается в состояние или логи; бот пытается удалить сообщение с паролем через API.

Уведомления отправляются после успешного сохранения заявки через `api/main.php` и `api/send.php`. Сообщение содержит только «На сайте появилась новая заявка.» и кнопку открытия админки. Имя, телефон, email, сообщение, номер заявки, IP и страница клиента не передаются ни в Telegram, ни на промежуточный Worker. Функция уведомления не принимает данные заявки. Недоступность Telegram не отменяет сохранённую заявку; автоматической очереди повторной отправки нет. Ошибки доставки записываются в PHP error log без токена и содержимого сообщения.

Документация API: https://core.telegram.org/bots/api#sendmessage, https://core.telegram.org/bots/api#setwebhook.
